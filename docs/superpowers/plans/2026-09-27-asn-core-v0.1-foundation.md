# ASN Core v0.1 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and release ASN Core v0.1 as a safe WordPress foundation plugin that installs beside the current Armenian Social Network system without replacing any live social feature.

**Architecture:** ASN Core remains a standalone, modular WordPress plugin whose root plugin file bootstraps focused services for database setup, member/profile reads, membership/billing integration, and admin diagnostics. WordPress user IDs remain authoritative; optional integrations such as PMPro and WooCommerce are detected defensively so missing plugins never cause a fatal error.

**Tech Stack:** WordPress/PHP, MySQL via `$wpdb` + `dbDelta()`, PMPro integration, WooCommerce integration, PHPUnit + WordPress test suite, PHP_CodeSniffer/WordPress Coding Standards, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-27-asn-core-design.md`

## Global Constraints

- WordPress remains the single user identity source; do not create a duplicate ASN user system.
- Existing profile data remains readable from WordPress user data/user meta.
- PMPro remains the free/premium entitlement layer.
- WooCommerce Subscriptions + WooPayments remain the billing source of truth.
- AtomChat remains live and untouched during v0.1.
- miniOrange / Tun SSO remains unchanged during v0.1.
- v0.1 must not replace Explore, Profile, Feed, registration, login, billing, or messaging.
- Existing member data must not be bulk-modified.
- Sensitive credentials must never be committed to GitHub.
- Database schema must use `$wpdb->prefix`; never hardcode `wp_`.
- Plugin activation and database setup must be idempotent and safe to run repeatedly.
- GitHub `main` contains deployable releases; implementation work is performed on `develop`.
- Production release version for this plan is `0.1.0`.

## Review Focus

1. PMPro is missing or temporarily disabled: ASN Core must load normally and report the integration as unavailable rather than fatal.
2. WooCommerce/WooCommerce Subscriptions is missing or disabled: diagnostics and helpers must return an unavailable state rather than fatal.
3. Activation runs more than once: all ASN tables and the schema version remain valid with no duplicate or destructive changes.
4. A requested WordPress user does not exist: member services return a controlled `null`/not-found result and never expose unrelated user data.
5. A non-administrator attempts to access ASN diagnostics: WordPress capability checks must deny access.

### Task 2: Versioned Database Installer

**Files:**

- Create: `tests/test-database.php`

- Produces: `ASN\Core\Database::table( string $name ): string`
- Option: `asn_core_db_version`
- Schema version: `1.0.0`

Initial tables:
- `{prefix}asn_profiles`
- `{prefix}asn_connections`
- `{prefix}asn_profile_views`
- `{prefix}asn_blocks`
- `{prefix}asn_reports`
- `{prefix}asn_notifications`

All user references store WordPress user IDs as unsigned bigint-compatible integer columns and are indexed.

- [ ] **Step 1: Write failing database tests**

Tests must assert:
- `Database::table('profiles')` uses the runtime WordPress prefix
- `Database::install()` creates all six tables
- running `Database::install()` twice leaves the same six tables and succeeds
- successful install stores `asn_core_db_version = '1.0.0'`
- failed installation does not falsely advance the database version

- [ ] **Step 2: Run database tests and verify failure**

Run: `composer test -- --filter Database`  
Expected: FAIL because `Database` is not implemented.

- [ ] **Step 3: Implement `Database`**

Use WordPress `dbDelta()` and `$wpdb->get_charset_collate()`.

Minimum schema responsibilities:
- `asn_profiles`: one row per `user_id`, timestamps, indexed searchable fields reserved for later profile indexing
- `asn_connections`: requester, recipient, status, created/updated timestamps, unique pair protection
- `asn_profile_views`: viewer, profile owner, viewed timestamp, indexes for owner/time and viewer/time
- `asn_blocks`: blocker, blocked user, created timestamp, unique pair
- `asn_reports`: reporter, target user/content identifiers, type/status/reason timestamps, moderation indexes
- `asn_notifications`: recipient, actor, type, object identifiers, read state, timestamps, recipient/read/time indexes

Do not import or copy existing member data during this task.

- [ ] **Step 4: Wire database installation into activation**

`Activator::activate()` calls `Database::install()`.

On failure:
- do not change live pages
- do not disable legacy functionality
- record a safe admin-visible failure state without exposing database credentials/errors to public users

- [ ] **Step 5: Run tests**

Run:
- `composer test -- --filter Database`
- `composer test`

Expected: PASS.

## Post-v0.1 Deployment Gate

After `v0.1.0` exists, connect the private GitHub repository to WordPress using the approved deployment mechanism (preferred: WP Pusher) and install ASN Core beside the current TunApp Customizations and AtomChat plugins.

Do **not** enable automatic production deployment from arbitrary `develop` commits.

The first production activation is successful when:
- ASN Core activates without a PHP fatal error
- all six ASN tables exist
- ASN diagnostics loads for administrators
- PMPro/WooCommerce status is detected correctly
- existing live social pages and AtomChat behave exactly as before
