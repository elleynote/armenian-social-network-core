# ASN Core v0.2 Profiles and Explore Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build testable ASN Core Profiles and Explore modules that use existing WordPress members as the source of truth, add a rebuildable searchable profile index, preserve current AtomChat messaging, and remain isolated from the live legacy Profile/Explore pages until manual cutover.

**Architecture:** WordPress users and user meta remain authoritative. ASN Core adds focused Profiles and Directory modules, a schema-v1.1.0 profile index for search/filtering, server-rendered shortcodes for parallel test pages, a small AtomChat adapter, and a repeatable WordPress-safe ZIP builder. Existing live shortcodes remain untouched until explicit cutover.

**Tech Stack:** WordPress/PHP >= 7.4, MySQL via `$wpdb` + `dbDelta()`, PMPro helper layer, AtomChat/CometChat launcher adapter, PHPUnit 9.6, WordPress Coding Standards, PowerShell/.NET ZIP tooling, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-28-asn-core-v0.2-profiles-explore-design.md`

## Global Constraints

- WordPress remains the single user identity source; do not create a duplicate ASN user system.
- WordPress user IDs remain the identity key everywhere.
- Existing member/profile source data stays in WordPress user data/user meta.
- `asn_profiles` is a rebuildable search/index layer, not a second user database.
- PMPro remains the entitlement layer; WooCommerce Subscriptions + WooPayments remain the billing source of truth.
- AtomChat remains live in v0.2; Better Messages is not introduced in this milestone.
- Tun SSO / miniOrange remains unchanged.
- Feed, registration, login, billing, checkout, subscription records, and prices remain unchanged.
- Live `[tac_user_profile]` and `[tac_contacts]` remain untouched during development.
- New test shortcodes are exactly `[asn_profile]` and `[asn_explore]`.
- Default directory page size is exactly 20 members.
- ASN database schema target is exactly `1.1.0`.
- Plugin release target is exactly `0.2.0`.
- Profile edits require authentication, ownership, nonce validation, allowlisted fields, sanitization, and escaped output.
- Public profile/directory data must never expose member email, password hashes, billing data, admin capabilities, tokens, or secrets.
- SQL must use safe `$wpdb` APIs/prepared statements; request values never enter SQL directly.
- Front-end CSS classes use the `asn-` prefix and must not globally style the existing site.
- Production ZIPs must have one top-level `asn-core/` folder and forward-slash ZIP entry paths.
- Implementation work remains on `develop`; tested releases are promoted deliberately.

## Pre-Implementation Release Gate

The production-tested v0.1 foundation must be frozen before v0.2 product code starts.

Use foundation commit:

```
ebda3b9365de891650aca063ffa043b6524eae0b
```

Create a release branch/ref at that commit, run CI, merge that exact foundation state to `main`, and tag `v0.1.0`. Do not include later v0.2 design commits in the v0.1.0 tag. This merge/tag is a shared-repository side effect: stop for the required confirmation immediately before executing it.

After the release point exists, continue v0.2 work from current `develop`.

## Review Focus

1. **Malformed or hostile directory filters/page values:** unknown dialect/proficiency/country, negative page, huge page, and SQL-like search input must be normalized safely and never alter SQL structure; Task 8 adds explicit tests.
2. **Stale/missing profile index row:** Profile display must still read the WordPress source of truth and Directory sync must recover the index rather than fatal; Tasks 3 and 4 add explicit tests.
3. **Profile edit with partial failure:** approved WordPress source fields that save successfully must remain authoritative even if the index refresh fails, with a controlled warning instead of rollback to arbitrary stale values; Task 6 adds an explicit test.
4. **AtomChat JavaScript unavailable at runtime:** Profiles/Explore must still render and the message control must fail closed without a JavaScript exception visible to the user; Task 9 adds an explicit test.
5. **Release archive path portability:** Windows-built ZIP entries must use `/`, not `\\`, and must exclude development files; Task 10 adds an explicit archive verification step.
